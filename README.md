# Academic QA: Multi-Source RAG Pipeline

A Retrieval-Augmented Generation (RAG) system for question-answering over academic PDF documents and transcribed YouTube lecture audio. The system combines local document processing, speech-to-text transcription via Whisper, dense semantic retrieval via ChromaDB, and stateful conversational inference powered by LangGraph and Groq's LLaMA 3.1 inference engine.

---

## 1. System Architecture

The project is split into two distinct pipelines:
1. **Ingestion Pipeline (`ingest.py`)**: Asynchronous/offline batch processing that downloads audio, transcribes speech, extracts text from PDFs, chunks documents, computes dense embeddings, and writes to a local vector store.
2. **Inference Pipeline (`app.py`)**: An interactive Streamlit application managing user queries, similarity retrieval from ChromaDB, graph-based message checkpointing via LangGraph, and generation via Groq API.

```
INGESTION PIPELINE:
  [ YouTube URL ]  ───>  yt-dlp / pydub  ───>  docs/youtube/*.mp4
                                                     │
                                             FasterWhisperParser
                                                     │
  [ data/*.pdf ]   ───>  PyPDFLoader  ───────────────┤
                                                     ▼
                                           Combined Documents
                                                     │
                                       RecursiveCharacterTextSplitter
                                         (chunk=2028, overlap=250)
                                                     │
                                                     ▼
                                           Document Chunks
                                                     │
                                          HuggingFaceEmbeddings
                                      (intfloat/multilingual-e5-large)
                                                     │
                                                     ▼
                                            ChromaDB Vector Store
                                               (docs/chroma/)

INFERENCE PIPELINE:
  [ User Query ]
        │
        ▼
  ChromaDB (Similarity Search k=3 with scores)
        │
        ├──> Chunks (Paragraph text)
        └──> Metadata (source, page, score)
        │
        ▼
  LangGraph Runtime
  ├── Checkpointer: MemorySaver (thread_id="streamlit_chat_session")
  ├── State: MessagesState
  ├── System Prompt (concise academic QA, strict grounding)
  └── LLM Node: ChatGroq (llama-3.1-8b-instant, temp=0.0)
        │
        ▼
  Streamlit Chat UI
  └── Assistant Response + Source Document Path + Reference Pages
```

## 3. Technical Breakdown of Components

### 3.1 Configuration (`config.py`)
Centralized settings class `Config` loaded as a singleton `config`.

| Parameter | Type / Default | Description |
|---|---|---|
| `YOUTUBE_VIDEO_URL` | `str` | Default YouTube video URL fetched for transcription. |
| `YOUTUBE_AUDIO_SAVE_DIRECTORY` | `"docs/youtube/"` | Staging path where downloaded audio tracks are stored. |
| `PDF_SOURCE_DIRECTORY` | `"data"` | Path containing input academic PDF documents. Automatically created if missing. |
| `CHROMA_PERSIST_DIRECTORY` | `"docs/chroma"` | Target on-disk directory for ChromaDB vector storage. |
| `EMBEDDING_MODEL_NAME` | `"intfloat/multilingual-e5-large"` | HuggingFace embedding checkpoint used for dense representations (1024-dimensional embeddings). |
| `CHUNK_SIZE` | `2028` | Maximum character length per text chunk. |
| `CHUNK_OVERLAP` | `250` | Character overlap between consecutive chunks to preserve contextual continuity across boundaries. |

### 3.2 Ingestion & Indexing (`ingest.py`)
Executed as a standalone script to build or refresh the vector store:

1. **Audio Ingestion & Transcription (`load_youtube_content`)**:
   - `YoutubeAudioLoader` invokes `yt-dlp` to download the audio stream to `docs/youtube/`.
   - `FasterWhisperParser` utilizes `faster-whisper` (CTranslate2-optimized Whisper engine) to transcribe speech content directly into LangChain `Document` objects containing segment text and timing metadata.
2. **PDF Ingestion (`load_pdf_content`)**:
   - Scans `data/` for files ending in `.pdf`.
   - Loads pages via `PyPDFLoader`, extracting raw text and preserving metadata (`source` filepath and `page` index, 0-indexed).
3. **Chunking**:
   - Merges YouTube transcription documents and PDF page documents.
   - `RecursiveCharacterTextSplitter` segments documents recursively across paragraph breaks (`\n\n`), single newlines (`\n`), and spaces using `chunk_size=2028` and `chunk_overlap=250`.
4. **Vector Embedding & Persistence**:
   - Initializes `HuggingFaceEmbeddings` with `intfloat/multilingual-e5-large` running locally via `sentence-transformers`.
   - Instantiates a persistent Chroma database via `Chroma.from_documents()`.
   - Invokes `vectordb.persist()` to write index collections and SQLite metadata to `docs/chroma`.

### 3.3 Inference & Conversational Graph (`app.py`)
A reactive Streamlit chat interface built around LangGraph stateful execution:

1. **Vector Store & Model Initialization**:
   - Connects to the pre-indexed Chroma database in `docs/chroma`. Halts execution with an informative UI banner (`st.error`) if the directory has not been populated.
   - Initializes `ChatGroq` targeting `llama-3.1-8b-instant` with `temperature=0.0` (deterministic outputs) and `max_tokens=400`.
2. **LangGraph Workflow**:
   - Graph definition using `StateGraph(state_schema=MessagesState)`.
   - State transition: `START -> "model" -> END`.
   - Node `call_model`: Injects an academic QA system prompt enforcing factual grounding, concise answers (maximum 3 sentences), and honest fallback ("I don't know") when evidence is insufficient.
   - State Checkpointer: `MemorySaver()` bound to session thread `streamlit_chat_session`. Ensures multi-turn conversation memory persists across the user's interactive session.
3. **Retrieval & Citation Formatting**:
   - On incoming prompt, runs `vectordb.similarity_search_with_score(prompt, k=3)` to retrieve top-3 semantic chunks.
   - Compiles retrieved paragraphs into a context block and constructs a `HumanMessage(content="Context: {current_context}\n\nQuestion: {prompt}")`.
   - Passes the payload to `app.invoke()` with thread ID configuration.
   - Extracts `source` path and deduplicated top `page` numbers from the retrieved documents.
   - Formats the displayed response with clean markdown metadata:
     ```
     <Answer text>

     **Source Document**: data/sample_paper.pdf
     **Reference Page Numbers**: 2, 3
     ```

## 4. Prerequisites

- **Python**: Version `3.11` (specified in `.python-version` and `pyproject.toml`).
- **Package Manager**: [`uv`](https://github.com/astral-sh/uv) (recommended) or standard `pip`.
- **System Binaries**:
  - **FFmpeg**: Required by `yt-dlp`, `pydub`, and `faster-whisper` for audio stream extraction and decoding.
    - *Windows*: `winget install Gyan.FFmpeg` or download from [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) and add `bin` to `PATH`.
    - *macOS*: `brew install ffmpeg`
    - *Linux*: `sudo apt-get update && sudo apt-get install -y ffmpeg`
- **Groq API Key**: A valid API key from [Groq Console](https://console.groq.com/).

## 5. Installation and Setup

### 1. Clone the Repository
```bash
git clone https://github.com/RIZVIQ/RAG-Chatbot.git
cd RAG-Chatbot
```

### 2. Environment Setup (using `uv`)
```bash
# Create virtual environment
uv venv

# Activate virtual environment
# On Linux/macOS:
source .venv/bin/activate
# On Windows (PowerShell):
.venv\Scripts\Activate.ps1

# Install all project dependencies
uv sync
```

*(Alternative with standard pip)*:
```bash
python -m venv .venv
source .venv/bin/activate  # or .venv\Scripts\activate on Windows
pip install -e .
```

### 3. Configure Credentials
Create a `.env` file in the project root:
```bash
cp .env.example .env
```
Edit `.env` and set your Groq API key:
```env
GROQ_API_KEY="gsk_your_actual_groq_api_key_here"
```

## 6. Running the Application

### Step 1: Place Your Documents
1. Copy target PDF files into the `data/` directory.
2. (Optional) To change the ingested YouTube video or embedding settings, update `YOUTUBE_VIDEO_URL` or chunking parameters in `config.py`.

### Step 2: Run Document Ingestion
Execute the ingestion script to process the documents and generate the Chroma vector store:
```bash
uv run python ingest.py
```
*Expected output*:
- Audio file downloaded to `docs/youtube/`
- Audio transcribed into documents via Whisper
- PDFs in `data/` parsed page by page
- Text split into overlapping chunks
- Embeddings generated and persisted into `docs/chroma/`

### Step 3: Start the Streamlit Chat App
Launch the web interface:
```bash
uv run streamlit run app.py
```
Open your browser at `http://localhost:8501`. Queries submitted through the chat bar will retrieve relevant chunks from `docs/chroma/`, generate grounded responses via Groq, and display source citations and page numbers.

## 7. Key Dependencies & Rationale

| Dependency | Purpose |
|---|---|
| `chromadb` | Lightweight, embedded vector database storing chunk embeddings and metadata locally on disk. |
| `faster-whisper` | Fast implementation of OpenAI's Whisper model utilizing CTranslate2 for GPU/CPU-accelerated local transcription. |
| `langchain` / `langchain-community` | Document loaders (`PyPDFLoader`, `YoutubeAudioLoader`), text splitters, and embedding abstractions. |
| `langchain-groq` | Native integration with Groq's high-throughput LPU inference API. |
| `langgraph` | Cyclical/stateful agent orchestration framework managing conversational state and `MemorySaver` checkpointing. |
| `sentence-transformers` | Runs local transformer embedding models (`intfloat/multilingual-e5-large`) without third-party API dependencies. |
| `pypdf` | Pure Python PDF parsing and text extraction. |
| `yt-dlp` & `pydub` | Extraction, downloading, and post-processing of media streams from YouTube. |
| `streamlit` | Reactive UI for real-time conversation and citations. |

## 8. Implementation Notes & Operational Considerations

- **First-time Model Download**: On the initial run of `ingest.py` or `app.py`, `sentence-transformers` downloads the `intfloat/multilingual-e5-large` weights (~2.24 GB) and `faster-whisper` downloads the Whisper model weights to local HuggingFace/CTranslate2 caches. Ensure sufficient disk space and network access during first-time execution.
- **Embedding Model Consistency**: The embedding model configured in `config.py` (`EMBEDDING_MODEL_NAME`) must remain identical between `ingest.py` and `app.py`. Changing the embedding model requires deleting `docs/chroma` and re-running `ingest.py`.
- **Memory Checkpointing Scope**: Conversation history in `app.py` uses `MemorySaver()` with a fixed session ID (`"streamlit_chat_session"`). Messages persist within the active Python process memory. Restarting the Streamlit server resets conversational memory while preserving the on-disk ChromaDB index.
- **Strict Answering Constraints**: The system prompt in `app.py` restricts responses to 3 sentences maximum and enforces strict grounding in retrieved context. If a query is outside the scope of the ingested documents, the model responds indicating insufficient knowledge rather than hallucinating.
